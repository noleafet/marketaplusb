# ETL API v1 and Strategy Versioning Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A read-only, key-authenticated `/api/v1/` REST API that lets an external ETL pull configuration, market, backtest, paper-trading and event data incrementally, with every record stamped by a content-hashed strategy/config version.

**Architecture:** Versioning (`apps/engine/versioning.py`, `apps/trading/events.py`) adds append-only `StrategyVersion`, `ConfigVersion`, `GridEvent` and `SessionSnapshot` rows at the points where the engine and paper trader already write. A new `apps/etl_api` app serves them plus existing tables through its own views, auth, throttling, cursor pagination and RFC 7807 errors, leaving the dashboard API under `/api/` untouched.

**Tech Stack:** Django 5.2, DRF 3.16, PostgreSQL/Timescale (raw SQL in `apps/engine/timescale.py`), Django `TestCase`. No new dependencies.

**Spec:** `docs/superpowers/specs/2026-10-30-etl-api-v1-design.md`

## Global Constraints

- All paths are relative to `backend/`. Run tests from `backend/` with `.venv/Scripts/python.exe manage.py test <label> -v 2`.
- No new Python dependencies (`requirements.txt` unchanged).
- `/api/v1/` is GET/HEAD/OPTIONS only; every other method returns 405 `method_not_allowed`.
- `/api/v1/` accepts only `Authorization: Bearer <key>`; `X-Engine-Token` and `ENGINE_ALLOW_PUBLIC_READS` do not apply.
- Key format: `mpb_` + 40 URL-safe random chars; stored as SHA-256 hex; `key_prefix` = first 12 chars.
- Default rate limit 120 requests/min per client; headers `X-RateLimit-Limit`, `X-RateLimit-Remaining`, `X-RateLimit-Reset`; 429 sets `Retry-After`.
- `page_size` default 500, max 1000; candles max 5000. Market windows max 400 days.
- Rows whose incremental key is later than `now − 5s` are never returned.
- All timestamps UTC ISO-8601 with `Z`.
- Errors: `application/problem+json`, `type` = `https://marketaplusb/errors/<slug>`.
- Environments: `backtest`, `walk_forward`, `paper`, `live`.
- `code_sha` comes from env `GIT_SHA`, default `"unknown"`.
- Canonical JSON: sorted keys, `separators=(",", ":")`, floats rounded to 10 significant digits, UTF-8.
- Engine/trading behaviour must not change: capture code only adds writes. The existing suites (`apps`) must stay green.
- The dashboard API (`/api/...`), its permission class and `REST_FRAMEWORK` defaults stay unchanged; v1 sets its own classes per view.

## Review Focus

1. **Concurrent first resolution of the same version:** two workers resolve an identical new config at once. Expect one row, no IntegrityError reaching the caller (Task 1 test `test_resolve_is_race_safe`).
2. **Several timestamp ties on one page boundary:** many fills share one `time`. The cursor walk must return each exactly once (Task 6 test `test_cursor_ties_across_pages`).
3. **Requests from multiple gunicorn workers:** the throttle must count across processes, not per process. The DB-backed window handles this (Task 5 test `test_throttle_counts_in_database`).
4. **Naive or offset timestamps in query params** (`2026-10-01T00:00:00`, `+02:00`): naive values are read as UTC, offsets are converted, and responses are always `Z` (Task 6 test `test_parse_naive_and_offset_dates`).
5. **Malformed or tampered cursor:** returns 400 `invalid_parameter`, never 500. A cursor from another endpoint returns 410 `cursor_expired` (Task 6 tests `test_bad_cursor_400`, `test_foreign_cursor_410`).

Hook rules:
- Settings save: resolve the version before and after `serializer.save()`. If the ids differ, `record_event("param_change", reason="settings_update", before=<old snapshot subset>, after=<new subset>, strategy_version=new)`, where the subsets are the keys of `diff_snapshots(old.snapshot, new.snapshot)`.
- `AnalysisRun.objects.create(... strategy_version=resolve_strategy_version())`.
- `CoinAnalysis.objects.create(... config_version=resolve_config_version(item["coin"].binance_symbol, item.get("params") or {}))`.
- `PaperSession.objects.create(... strategy_version=resolve_strategy_version(), config_version=resolve_config_version(coin.binance_symbol, item.get("params") or {}))`, then `snapshot_session(session, "start")`.
- Both `PaperFill(...)` constructors get `strategy_version_id=session.strategy_version_id, config_version_id=session.config_version_id`.
- Rebalance (inside `if strategy.rebalances > rebalances_before`): `record_event("rebalance", session=session, reason=strategy.last_rebalance_reason, after={"range_low", "range_high", "active_levels"} taken from _grid_log_payload)` + `snapshot_session(session, "rebalance")`. Run this **after** the session save at the end of `_tick_session`, so the snapshot holds post-tick state; collect a flag during the tick.
- `pause_session`/`resume_session`/`stop_session`: event + snapshot with the matching type, inside the existing `if` block after `save`. The retire path uses type `retire` with `reason` = the existing `reason` string.
- `set_kill_switch`: `record_event("kill_switch", environment="live", reason=state.kill_reason, after={"engaged": engaged})`. Add `environment: str = "paper"` to the `record_event` signature for this.
- `handle_daily_analysis`: after the analysis finishes, `snapshot_session(s, "daily")` for each `PaperSession` with status `active` or `paused`.
- `Dockerfile`: `ARG GIT_SHA=unknown` and `ENV GIT_SHA=$GIT_SHA` before `COPY . .`. `compose.yaml`: under each `build: ./backend` service, switch to `build: {context: ./backend, args: {GIT_SHA: "${GIT_SHA:-unknown}"}}`. `DEPLOYMENT.md`: add `GIT_SHA=$(git rev-parse HEAD) docker compose build`.

Logs whose message ends in `paper session paused.` / `resumed.` and whose payload has `session_id` → `pause`/`resume` events. Anything else is skipped.
- Reverse: `migrations.RunPython.noop`.
